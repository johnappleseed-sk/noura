# Product Generator

## Overview
The Product Generator enriches existing commerce products with missing content and identifiers for operational and storefront use.

It supports:
- AI-assisted product description generation
- Barcode generation (EAN-13)
- QR code payload generation and image rendering
- Search/select workflow for existing products in the admin dashboard

## Business Rules
- Generation is product-scoped and runs against existing products.
- Only missing fields are generated by `generate-missing`.
- Per-field endpoints are idempotent: if a field is already present, it is not overwritten.
- Barcode values must be unique across `products.barcode`.
- QR code value defaults to a product URL template with `{id}` replacement.
- Generation and search endpoints are restricted to `ADMIN` role.
- Canonical write is in commerce DB; inventory updates are mirrored asynchronously.

## Architecture
- Canonical domain: commerce `products` table.
- Bridge mapping: `product_generator_bridge` links commerce product UUID to inventory product UUID.
- Mirror jobs: `product_generator_mirror_jobs` stores durable async sync jobs.

Primary flow:
1. Admin searches/selects a product.
2. Admin triggers generation endpoint.
3. Missing values are generated and saved on commerce product.
4. Mirror job is queued for inventory sync.
5. Scheduled worker retries mirror until success or terminal state.

## Backend
Main endpoints (version prefix defaults to `/api/v1`):
- `GET /products/search?q=...`
- `GET /products/{id}`
- `POST /products/{id}/generate-missing`
- `POST /products/{id}/generate-description`
- `POST /products/{id}/generate-barcode`
- `POST /products/{id}/generate-qr`
- `GET /products/{id}/barcode-image`
- `GET /products/{id}/qr-image`

Service modules:
- `ProductEnrichmentService` / `ProductEnrichmentServiceImpl`
- `ProductDescriptionGenerationService` (LLM + fallback)
- `ProductCodeImageService` (barcode/QR image rendering)
- `ProductMirrorSyncWorker` + `ProductInventoryMirrorService`

Persistence changes:
- `products.target_audience`
- `products.barcode` (unique when non-null)
- `products.qr_code`
- `product_generator_bridge`
- `product_generator_mirror_jobs`

## Frontend
Admin UI location:
- `frontend/admin-dashboard/src/pages/ProductGeneratorPage.jsx`

Behavior:
- New **Find Existing Product** section supports universal search by ID, name, or SKU.
- Search result cards show missing/present status for description, barcode, and QR.
- Selecting a product pre-fills product parameters and output section.
- Actions:
  - Generate Missing Fields
  - Generate Description
  - Generate Barcode
  - Generate QR Code
- Barcode/QR images are fetched from image endpoints and rendered in output.
- Mirror warning message is shown when sync is blocked (for example missing bridge mapping).

## Configuration
Key properties:
- `app.product-generator.product-url-template`
- `app.product-generator.llm.*`
- `app.product-generator.mirror.*`

See `docs/setup.md` for environment variable names and defaults.

## Usage Example
1. Search for product: `GET /api/v1/products/search?q=SKU-1001`
2. Select product id from results.
3. Generate missing fields:
   - `POST /api/v1/products/{id}/generate-missing`
4. Fetch generated images:
   - `GET /api/v1/products/{id}/barcode-image`
   - `GET /api/v1/products/{id}/qr-image`

## Edge Cases
- Blank search query returns empty list.
- Product not found or inactive returns not-found response.
- If no fields are missing, generation endpoints return existing values with `*_generated=false`.
- LLM failures fall back to template description generation.
- Missing bridge mapping does not block canonical save; mirror job is marked `BLOCKED_MAPPING` and warning is returned.

## Notes
- Legacy endpoint `/api/v1/admin/product-generator/generate` remains for backward compatibility.
- The product-scoped endpoints are the canonical workflow for existing-product enrichment.
